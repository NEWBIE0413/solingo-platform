# 브리프: 젬 경제 · 상점 · 프로필 · 학습 편입  (base: main c77c029)

## 의도
지금 이 앱의 동기 장치는 XP와 연속 출석뿐이다. 듀오링고가 오래 붙잡는 이유의 절반은 **퀘스트 → 보상 → 상점 → 꾸미기**의 순환이다. 이 앱은 두 사람(커플)이 쓰고 서로의 프로필을 본다 — 꾸미기가 의미 있는 이유가 바로 거기다. 클론에는 이 층이 없다(상점 = 하트 채우기·Pro 결제, 퀘스트 = 누적 XP 진행바, 프로필 없음). 이번 과제는 그 층을 놓는 것이다.

동시에 사이드바를 정리한다. 히라가나·약점 복습은 "학습"의 일부이지 별도 메뉴가 아니고, 레벨 결과는 "나"에 대한 정보라 프로필에 속한다.

## 재화 — 젬
- `user_progress.gems integer not null default 0`. XP(points)는 리더보드용으로 그대로 둔다. 젬은 퀘스트로만 번다.
- 젬은 돈이다. **이중 지급이 이 과제에서 가장 무서운 버그**다 — 지급은 반드시 유니크 제약 뒤에서.

## 퀘스트 (KST 일 단위, 매일 리셋)
| key | 조건 | 젬 |
|---|---|---|
| lesson1 | 오늘 레슨 1개 완료 | 5 |
| lesson3 | 오늘 레슨 3개 완료 | 10 |
| xp50 | 오늘 XP 50 | 10 |
| practice1 | 오늘 약점 복습 1회 완료 | 10 |
| kana1 | 오늘 히라가나 세션 1회 완료 (일본어 코스 사용자만 노출) | 5 |
| couple | 오늘 커플 둘 다 출석 (둘 다 받음) | 15 |
| streak7 / streak30 / streak100 | 연속 출석 도달 (일회성, day 없음) | 50 / 200 / 500 |

- 데이터원: `daily_activity`를 확장한다 — `xp int default 0`, `practice int default 0`, `kana int default 0`, `frozen boolean default false`. `lib/streak.recordActivity`에 kind 인자를 두어 레슨/복습/가나 완료가 각자 열을 올리고, `submitAnswer`가 포인트를 줄 때·`/api/kana/state`가 xpDelta를 받을 때 `xp`를 더한다. (연습 모드는 포인트가 없으니 xp 0.)
- 수령 모델: 퀘스트 페이지는 진행률을 보여주고, 달성하면 **"받기"** 버튼. `quest_claims(user_id, quest_key, day)` PK(user_id, quest_key, day) — 일회성 퀘스트는 day='' 로. 수령 = 트랜잭션 안에서 insert 성공 시에만 gems 가산. 이미 받았으면 "받음".
- 클론의 누적 XP 퀘스트(QUESTS 상수)는 제거한다.

## 상점 (`constants.ts`의 SHOP_ITEMS, DB 테이블 아님)
| key | 종류 | 이름 | 젬 | 비고 |
|---|---|---|---|---|
| freeze | 소모품 | 연속 출석 보호 | 50 | 최대 2개 보유. 하루 빠져도 개인·커플 연속이 끊기지 않음 |
| frame_* | 꾸미기 | 아바타 테두리 3종 | 30·60·100 | 색/모양은 네 판단 |
| title_* | 꾸미기 | 칭호 5종 | 20~80 | 예: "가나 정복자", "새벽형 학습자", "커플 파워" — 이름은 네가 더 좋게 |
| mascot_* | 꾸미기 | 마스코트 스킨 3종 | 80 | public/mascot.svg 변형(색). SVG 직접 만들어도 됨 |
- `user_items(user_id, item_key, qty, acquired_at)` PK(user_id, item_key). 구매 = 트랜잭션: gems 충분 확인 → 차감 → qty+1. 꾸미기는 qty 1 고정(재구매 불가).
- `user_progress.equipped jsonb` — {frame, title, mascot}. 장착은 프로필에서.
- 하트 채우기 항목은 EVERYONE_IS_PRO일 때 숨긴다(의미가 없다). "슈퍼 이용 중" 표시는 유지.

## 연속 출석 보호(freeze)의 의미론
`lib/streak.ts`에서 연속을 셀 때 뒤로 걸어가다 **비어 있는 날**을 만나면: 그 사용자에게 freeze 재고가 있으면 하나 소모(qty-1)하고 그 날에 `daily_activity` 행을 `frozen=true, lessons=0`으로 넣은 뒤 계속 센다. 연속 이틀 결석은 두 개가 필요하다. 커플 연속에서 frozen 날은 그 사람이 출석한 것으로 친다. 읽을 때 소모하는 방식이라 멱등해야 한다(행이 생기면 다음 읽기에선 더 소모하지 않음).

## 프로필 `/profile` (사이드바 "프로필")
- 상단: 장착한 테두리를 두른 아바타, 이름(수정 가능), 칭호, 마스코트 스킨.
- 숫자: XP · 젬 · 연속일 · 최고 연속 · 완료 레슨 수 · 가입일.
- 커플 카드(연결돼 있으면): 상대 이름·아바타·오늘 출석 여부.
- **레벨 테스트 결과**: 기존 `app/(main)/level/level-view.tsx`를 여기서 렌더. 관리자 드롭다운·`?user=`도 그대로 동작해야 한다(`/level`은 `/profile`로 리다이렉트).
- 보유 아이템과 장착 UI.
- 테두리·칭호·마스코트는 **리더보드 행에도** 보여야 꾸밀 이유가 생긴다.

## 학습 편입
- `/learn` 유닛 길 위에 카드 2개: **히라가나 훈련**(활성 코스가 일본어 가나/일본어 JLPT일 때만, → /kana)과 **약점 복습**(→ /practice, 약한 문항 수 표시). 기존 컴포넌트를 재사용하되 유닛 배너와 시각적으로 구분되게.
- 사이드바에서 히라가나·약점 복습·레벨 결과 제거. 최종: 학습 / 리더보드 / 퀘스트 / 상점 / 출석 / 프로필. proxy.ts의 보호 경로에 /profile 추가.

## 경계
- 스키마는 **추가만**(열·테이블). 이름 변경·삭제 없음. 재시드 없음. content/ 손대지 않음.
- 레슨 러너의 즉시 판정 흐름(quiz.tsx의 check/submitAnswer)은 그대로 — 여기에 젬 로직을 끼우지 않는다(퀘스트는 daily_activity를 읽어 판단).
- 하트는 무제한 유지. 한국어 UI. 배포는 내가 한다.

## 성공 기준 (로컬, dev 서버 + QA 계정)
1. 레슨 1개 완료 → /quests에 lesson1 달성 → "받기" → 젬 +5 → 새로고침 후 "받음", 재수령 불가(DB quest_claims 1행).
2. 상점에서 테두리 구매 → 젬 차감 → /profile에서 장착 → /profile과 /leaderboard 양쪽 아바타에 테두리.
3. freeze 구매 → DB에서 어제 daily_activity 행 삭제 → /streak 조회 → freeze 소모(qty 1→0), frozen 행 생성, 연속일 유지. 두 번째 조회에서 추가 소모 없음.
4. 사이드바 6항목. /learn 상단 카드 2개. /profile에 레벨 결과 표시, /level → /profile 리다이렉트.
5. `pnpm exec tsc --noEmit` 클린. 기존 레슨 판정 7ms대 유지.

## 끝내는 법
main(c77c029)에서 브랜치 → 구현 → `pnpm run db:push`(로컬) → 검증 → 커밋 → 이 브리프 경로와 함께 회신: 한 일 / 바뀐 파일·커밋 / 성공 기준별 결과 / 못 한 것. 구현 판단(색·이름·레이아웃)은 네 것이다 — 이 문서는 계약이지 대본이 아니다.
